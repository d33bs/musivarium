# Investigating the 90-second Whisper Tiny repetition

## Summary

The benchmark's 90-second synthetic clip (`docs/voice-evaluation.md`) produced a severe decoder-loop hallucination ("the third one was the third one" repeated 74 times, 152.08% WER). Delegated subagents to isolate the cause were unavailable (provider rate limit), so this was diagnosed directly with a bounded Node script calling the actual installed `@huggingface/transformers` 4.3.2 pipeline on the already-generated clip audio, outside the browser. This is real local Whisper Tiny English inference on real (synthetic-speech) PCM, not a simulated result.

**Conclusion: this is a genuine Whisper Tiny English decoder hallucination on specific audio content, not a chunk/stride merge bug in this app or in Transformers.js. No production ASR configuration was changed.** Instead, the UI now detects and flags likely decoder loops so a user reviews them before saving (`src/voice/quality.ts`).

## Method

Ran `pipeline('automatic-speech-recognition', 'onnx-community/whisper-tiny.en', { revision: '794207fec2761281fe63a23a94b7e9f53a4efbc1', dtype: 'q8', device: 'cpu' })` directly in Node against the exact merged 90-second PCM file already generated by the benchmark (`synthetic-10-long-review-90s.f32`, 1,440,000 samples / 90.0 s), varying only the chunking options passed to the transcriber call, one variable at a time:

| Config                                                                      | Result                                                                                                                                                                                                                  |
| --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chunk_length_s: 25, stride_length_s: 5` (production default)               | Hallucinates: "the third one was the third one" × 74, full reference content otherwise present (571 words)                                                                                                              |
| `chunk_length_s: 25, stride_length_s: 5, condition_on_previous_text: false` | Identical output to the default — this pipeline parameter has no observed effect, confirming it is not a usable mitigation here                                                                                         |
| `chunk_length_s: 25, stride_length_s: 10`                                   | Still hallucinates (619 words, same loop, slightly different boundary wording)                                                                                                                                          |
| `chunk_length_s: 28, stride_length_s: 4`                                    | Still hallucinates, different loop phrase ("the third object is the third object" × 71)                                                                                                                                 |
| `chunk_length_s: 25, stride_length_s: 5, return_timestamps: true`           | Still hallucinates (394 words, shorter loop but still present)                                                                                                                                                          |
| `chunk_length_s: 20, stride_length_s: 5`                                    | No repeated phrase, but only 195 words recovered — the final anchor sentence ("Plum bicycle marks the final crossing…") is silently missing from the merged output                                                      |
| `chunk_length_s: 30, stride_length_s: 5`                                    | No repeated phrase, but only 106 words recovered, ending mid-sentence — much more content lost                                                                                                                          |
| no chunking options (pipeline default)                                      | Transformers.js warns "Attempting to extract features for audio longer than 30 seconds" and truncates to 80 words (first ~30 s only), confirming Whisper's native 30-second window without explicit long-audio chunking |

## Interpretation

- The hallucination reproduces across multiple chunk/stride configurations with different exact wording, which means it is **not** a fixed merge-boundary artifact of the default 25 s/5 s setting. It tracks specific audio content (the "second crossing" / StarDist-comparison segment of this synthetic clip), a known failure mode where small Whisper variants enter a repetition loop on certain inputs — especially synthesized TTS speech, which has less natural pause/intonation variation than human speech.
- `chunk_length_s: 20` and `chunk_length_s: 30` happened to avoid the specific loop content falling in a vulnerable window, but both configurations **silently dropped real trailing audio** instead. That is a worse defect for an app than an occasional hallucination that a user can see and correct: it has no edit-time signal at all. Neither alternate config is adopted.
- `condition_on_previous_text: false` had zero observed effect on this pipeline/runtime combination, so it is not a verified mitigation here and was not adopted.
- This Node-direct experiment excludes the browser WASM runtime, worker messaging and real AudioWorklet capture; it isolates exactly the decoder/chunking behavior in question using the real installed library and real model weights.

## Decision

No change to `ASR_CHUNK_OPTIONS` (`src/voice/asr-config.ts`, still `{ chunk_length_s: 25, stride_length_s: 5 }`). Changing it based on this one clip would trade a visible, correctable hallucination for invisible content loss on other recordings — worse for an app whose whole point is a user-reviewed, editable transcript.

Added `src/voice/quality.ts`: `transcriptWarnings(text)` flags any 6-word phrase repeated 8+ times and shows a plain warning in the Voice notes editor (`#voice-transcript-warning`), both right after transcription and on manual edits. It never rewrites or deletes text — only a human correction is trustworthy here, since the detector cannot distinguish a real hallucination from a legitimately repeated scientific phrase. Saving remains allowed; the warning is advisory.

## What remains unresolved

- The underlying Whisper Tiny English hallucination is not fixed and cannot be fixed from this app alone; it is model/decoder behavior. Users dictating long paragraphs may still see it, now with an on-screen warning instead of a silent bad save.
- A full before/after benchmark of Whisper Base English or a verified Moonshine model against this clip was not completed in this session (the subagents tasked with it failed on a provider rate limit before producing results). If that comparison is wanted, it should be run as a fresh, explicit task — do not reuse this document's conclusions as model-comparison evidence.
- This investigation used one 90-second clip's audio; it is not a statistically robust characterization of hallucination frequency across content or speakers.
